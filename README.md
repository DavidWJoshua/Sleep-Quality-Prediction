# Sleep Quality Prediction

A full-stack research & demo project for generating synthetic sleep/performance datasets and building models to predict sleep quality from wearable and smartphone sensor signals. This repository includes dataset generation utilities, a Django web UI, example analysis code, and deployment configuration (Vercel).

Highlights
- Synthetic dataset generator that produces 100k records with physiologic and behavioral features (data.py).
- Large pre-generated CSV datasets included for experimentation: `synthetic_sleep_performance_dataset_100k.csv` and `one data.csv`.
- Django-based web application scaffold (manage.py, templates, static files) for visualizing and interacting with predictions.
- Device/physiology features simulated: skin temperature, SpO₂, heart rate, EDA, screen time/brightness, activity, and sleep-stage related targets (sleep efficiency, REM/deep %).

Why this project
- Sleep quality is influenced by a combination of physiological signals and daily behaviors. This repo provides a controlled synthetic dataset to prototype feature engineering and model architectures before collecting real-world data.
- The generator provides interpretable weighting for a custom "Sleep Quality Value" and a simulated PSQI for ground-truth comparisons.

Overview

The repository synthesizes realistic wearable and behavioral measurements and computes target metrics used in sleep research: sleep efficiency, sleep latency, WASO, REM and deep sleep percentages. It implements a combined metric called *Sleep Quality Value* and a simulated PSQI score. The project is intended for exploratory model development, feature engineering, education, and demoing a web interface for results.

Datasets

There are two dataset files committed to the repository:
- synthetic_sleep_performance_dataset_100k.csv (~10 MB): a generated dataset with 100,000 rows. Use this for training/benchmarking.
- one data.csv (~13 MB): additional CSV data included by the author. Verify contents before using in production.

Note: Both CSV files are large and will increase clone time. If you plan to keep the repo lightweight, consider removing large data files and storing them in a cloud bucket or Git LFS.

Data generation (data.py)

The `data.py` script generates N_RECORDS (default 100,000) records of simulated sensor and behavioral features, computes a weighted Sleep Quality Value and a simulated PSQI score, and writes the result to `synthetic_sleep_performance_dataset_100k.csv`.

Key behaviors in data.py:
- Time-stamped synthetic data (Date + Time columns)
- Physiological signals: skin temperature, SpO₂, heart rate, EDA-like signal
- Behavioral signals: screen time, screen brightness, activity minutes, stress scores
- Targets: sleep efficiency, latency, REM %, deep sleep %, WASO
- Per-row random weight factors used to compose a custom Sleep Quality Value
- Simulated PSQI generated by combining negative metrics (WASO, latency, low efficiency) with noise

Installation & Quickstart

1. Clone the repository

   git clone https://github.com/hkhearts/Sleep-Quality-Prediction.git
   cd Sleep-Quality-Prediction

2. Create a virtual environment and install dependencies (recommended)

   python -m venv .venv
   source .venv/bin/activate   # macOS / Linux
   .venv\Scripts\activate    # Windows PowerShell
   pip install -r requirements.txt

3. Generate the synthetic dataset (optional — a generated CSV is already committed)

   python data.py

   This will write `synthetic_sleep_performance_dataset_100k.csv` to the repository root.

4. Run Django locally (development)

   python manage.py migrate
   python manage.py runserver

   Visit http://127.0.0.1:8000/ to view the web UI. Check `templates/` and `Ui/` for pages and static assets.

Model training & evaluation

This repository contains example analysis code in `analyzer/` and `sleepanalyzer/` folders. Typical steps to train a model:

1. Preprocess the CSV: feature selection, normalization, datetime handling, train/test split.
2. Train model(s) using scikit-learn, XGBoost, or any framework you prefer. Requirements include scikit-learn and joblib for model persistence.
3. Evaluate with regression metrics (RMSE, MAE, R²) for continuous Sleep Quality Value or classification metrics if you binarize (good vs poor sleep using PSQI > 5).
4. Save the trained model to disk (joblib or pickle) and wire it into the Django app for inference.

Example CLI (very high level)

   python train.py --data synthetic_sleep_performance_dataset_100k.csv --target "Sleep Quality Value" --output models/sleep_quality.joblib

Deployment

The repository contains `vercel.json` and `.vercelignore` to facilitate deployment. This project was likely configured to deploy a static front-end or serverless functions. If you plan to deploy the Django app, consider the following:
- Vercel is optimized for front-end frameworks. For a full Django app, consider using Render, Heroku (deprecated but still used), Fly.io, or a Docker container on any cloud provider.
- Use WhiteNoise to serve static assets (already in requirements.txt).
- Use a production-grade database (Postgres) and set environment variables for secrets.

Best practices for production
- Remove committed large datasets and use cloud storage (S3, GCS) or Git LFS.
- Add a .env template and never commit secret keys.
- Use CI to run linting and tests before deployment.
- Add model versioning and a model evaluation pipeline to reproduce experiments.
